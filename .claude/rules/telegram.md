# Copilot on Telegram (team bot)

Gotchas that change how code must be written. Full reasoning and history: `docs/architecture/telegram.md`.

- `convex/lib/telegramApi.ts` is the ONLY code that talks to `api.telegram.org` or reads `TELEGRAM_BOT_TOKEN` (guard `telegramApiPort.test.ts`). Never `fetch` the Bot API elsewhere. Never log the token, the request URL, a chat id next to a name, any message text, or the Bot API `description`.
- Button and prompt actions go ONLY through `convex/lib/telegramActions.ts`: `authorizeTelegramActor` (org of the tapped card, live member, module, RBAC like the public mutation) before every port; ids from `callback_data` via `normalizeId` of the expected table. No other telegram file references domain `internal.*` or cores (guard `telegramActionsPort.test.ts`). A port that throws becomes `ConvexError({kind:"telegramFailure"})` so the whole mutation rolls back.
- Notifications reach Telegram only through `createNotification` (fan-out after the insert, no network in the mutation). Every notification type needs a template or an `IGNORED_FOR_TELEGRAM` entry (parity test). Conversation content is delivered only to members who still have `inbox:view_own`.
- Pipeline hooks live only in `lib/telegramRelay.ts` (`internalReceiveMessage`, `internalCommitAiReply`, accept/reject/cancel handoff cores, dispatch failure); they never throw into the caller and never relay a group.
- AI-reply relay carries ONLY the committed reply with `metadata.aiReply` (queue item `requestedVia` telegram* + `instructedBy`), once, to that member, with the `AI_BACK_IN_CHARGE` line. Focus never relays AI replies.
- Draft-first (D23): an instruct/regenerate requested from the bot (`requestedVia` on a `return_to_ai`/`coach` item) ALWAYS becomes a draft (`forceSuggest`), even with the attendant in autopilot. Countdown auto-send applies only to drafts the member asked for from the bot (`draftAutoSendable`: `aiDraft.requestedVia` telegram* AND `instructedBy` = the member), checked at delivery and at send time.
- Telegram turns write with `via:"telegram"` (`telegram_auto` in event turns). `instructAttendant` with the attendant in autopilot is two-phase, except in assistant AUTO mode (`assistantMode` in the executor scope). `sendCustomerReply` is always two-phase. The prompt must never promise a text confirmation: "toque em ✅ Confirmar no cartão".
- Assistant modes are `suggest` (default) and `auto` (`effectiveAssistantMode`; `allowAutoMode:false` or 3 undos in 1 h force `suggest`). Handoffs and stuck follow-ups are never resolved by the assistant: card + read-only "💡 Sugiro" in any mode. The automatic turn runs ONLY for `new_message` of the focused conversation (focus < 6 h), uses `autoAllowed` tools (never `acceptHandoff`), and a task created with a focus and no `leadId` gets the focused lead.
- Event turns (automatic/suggestion) run in `assistantThreadId` with `assistantTurnLock`; free text in `copilotThreadId` with `turnLock`. Undo steps (`telegramAutoSteps`) carry `after` and are skipped on drift; task reopen only via `reopenTaskCore`; undo, veto and auto-send live in `lib/telegramActions.ts`.
- Revocation has one door: `revokeTelegramLink` (status, audit `telegram.unlinked`, cleanup: farewell, `deleteMessage` ≤ 48 h, chat pointer). Member removal calls `revokeTelegramLinksForMember`. "Member alive" = `isLinkMemberAlive`, re-checked on every update; never trust a link row alone.
- Card text is blocks separated by a blank line; the org name only when `CardContext.multiOrg`. E-mail addresses are hidden ONLY in discreet mode (`scrub`); full mode shows them (a Pix key can be an e-mail).
- Webhook: wrong/missing secret → 401; 200 always after a valid secret, except when the ingest mutation itself failed and nothing was stored (500, so Telegram retries; ingest is idempotent by `update_id`). A non-2xx blocks that chat's queue. Callback acks go in the response body.
- Decide in a mutation, send in an action: routing mutations return `replies`/`edits`; only actions call the port. A message carries one `reply_markup` (inline wins over `Reply.persistentKeyboard`).
- `parse_mode: "HTML"`: every dynamic value through `escapeHtml`; LLM/customer Markdown through `markdownToTelegramHtml`; long text through `splitMessage`. Private chats only: a group must never receive CRM data.
- Commands (`telegramCommands.ts`) read only through bounded indexes, authorize with `resolveTelegramViewer` + RBAC per list, never write domain tables. F2 callbacks (`cmd:`/`pg:`/`fc:`/`mu:`/`org:`/`ob:`) are parsed BEFORE `handleTelegramCallback`, and every id in them is re-validated (`normalizeId`, same org, ownership). Mute applies to ALL active links of the chat.
- Reports (`telegramReports.ts`): the hourly tick stamps the local date BEFORE scheduling; `internalSendReport` with `trigger:"command"` (`/hoje`) never stamps; data only through `internalBuildReportData` (bounded indexes, "50+" caps, no `.collect()`).
- Limits (D25): every file the MEMBER sends reserves quota FIRST (`internalReserveFileQuota`, released on failure; unknown size = the cap, trimmed after download), uses the inbound allowlist (`isAllowedDocument`) plus `sniffMatchesMime`. Relayed CUSTOMER files use no quota. Every bot send claims a pacing slot ONCE (`claimTelegramSendSlot`) and reschedules itself at `sendAt` without claiming again.
- Files: customer → Telegram by storage URL (photo/voice) or upload (document/audio), never a Telegram `file_id` and never `MediaKey` material; Telegram → customer only through `whatsapp.internalSaveInboundAttachment` and `internalSendMessageCore` with `attachments`; unsent drafts go through `discardPromptDraft`; dispatch failures reach the card only via `maybeNotifyTelegramSendFailed`. Voice/photo bytes are deleted after Whisper/vision.
- DEV ≠ PROD bots, each deployment with its own token. The webhook URL is always `${CONVEX_SITE_URL}/webhooks/telegram/platform`; never add a URL override. Ops in `opsTelegram.ts` are `internalAction`, `dryRun` default true, and never print the token or the secret.
- Schema is additive: fields for later phases stay `v.optional`; new telegram tables go to `retention.ts` and `EXCLUDED_BACKUP_TABLES`. Tests always stub `fetch` (`vi.stubGlobal`) and use fake tokens (`123456:FAKE-TOKEN-…`).
